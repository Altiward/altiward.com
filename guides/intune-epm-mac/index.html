Deploy Altiward on Intune-managed Macs

Use Intune to deploy Altiward alongside SAP Privileges. This checklist points you to the configuration and install docs, then shows how to confirm the deployment is working.

Last reviewed October 2026Microsoft IntunemacOS 13 or later

SAP Privileges remains responsible for granting admin. Altiward checks membership, records the session and adds configurable expiry enforcement, console revocation and SIEM export. Intune distributes the package and profiles; Altiward does not need a direct Intune API integration.

1. Prepare the server and managed Macs

Follow the Altiward install guide to bring up the server and console. Macs need macOS 13 or later, with SAP Privileges already configured.

The data-handling document lists what leaves each Mac.

2. Configure the agent and Privileges profiles

Use the example Altiward agent settings as your reference. Deploy the settings in the com.altiward.agent domain through Intune:

  • ServerURL points to your Altiward agent endpoint.
  • EnrollmentToken allows the Mac to enroll with your server.
  • PermanentAdmins lists IT and break-glass accounts that Altiward must leave alone.
  • ExpiryEnforcement defaults to alert. Set it to enforce to remove overdue rights, excluding accounts in PermanentAdmins.

Include the login-items profile and add the Altiward hook settings to your existing corp.sap.privileges profile. Keep one managed source for those Privileges settings.

3. Keep the managed admin account separate

If you use macOS LAPS, put its managed account name in PermanentAdmins. Altiward excludes listed accounts from unexpected-admin findings and expiry enforcement. Password management stays with your MDM. See how Altiward treats permanent admins.

4. Deploy and validate the whole workflow

Deploy the agent package from GitHub Releases to your managed Macs, following the install guide. Confirm the deployment:

  1. Confirm that the Mac enrolls and appears in the console's Fleet view.
  2. Request admin through SAP Privileges with a test reason. Check that Altiward records the user, Mac, reason and expiry.
  3. End the session and confirm that the admin rights and console record agree.
  4. Test your chosen expiry policy and console revocation while the Mac can reach the server.
  5. Confirm delivery to your SIEM using the Altiward SIEM guide.

Use the install guide as the reference for package changes, enrollment, backups and upgrades.
