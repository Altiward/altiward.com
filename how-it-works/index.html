What happens when someone stops SAP Privileges' timer

SAP Privileges takes admin rights back with a countdown that runs in the person's own session. With admin rights, they can stop it, and the rights stay. Altiward's agent runs as root, keeps its own record of the expiry and checks the Mac's admin group directly.

  1. 1 · 14:02SAP Privileges
    Admin granted

    Reason: “Install the printer driver”. Allowed for 30 minutes. Privileges starts its countdown.

  2. 2 · 14:10The person
    The timer is stopped

    Now admin, they stop the Privileges agent that runs the countdown. Nothing on the Mac will take the rights back.

    Within five minutes, Altiward's agent sees the timer isn't running and raises a High finding.

  3. 3 · 14:32Altiward agent
    The grant expires

    Altiward kept its own record of the expiry. The account is still in the admin group, and the five-minute grace period starts.

  4. 4 · 14:39Altiward agent
    Rights removed

    At a heartbeat after the grace period, the agent removes the rights and records how the session ended.

Illustrative session with enforcement enabled and the default five-minute grace period. The times are an example, not an enforcement deadline; the default policy alerts without removing rights.

You choose what the agent removes

The agent checks at each heartbeat. Integrity checks can identify changes to the monitored components. If the agent stops checking in, the server flags a loss of visibility; it can't establish everything that happened while the agent was unavailable.

Couldn't they stop Altiward too? The agent is a root LaunchDaemon. Its tamper checks alert if that LaunchDaemon or its signature changes, and the server raises a finding when a Mac stops checking in.

Review the example agent profile before you change the policy. Removal is off by default. With OutOfBandEnforcement on enforce, an admin you haven't listed in PermanentAdmins is removed, including a LAPS account or hidden management account.

Revoke an admin account without a recorded grant

The account contractor holds admin rights on C02MVEHQGKMQ, with no grant on record. Here's how you take its rights away, in screenshots of the console with example data.

The same button revokes an approved session early. Revoking removes the admin rights; the account itself stays for you to deal with. Accounts that should always be admin, like your macOS LAPS account, are listed in Altiward's profile, never flagged or removed, and each use of one is recorded as evidence. By default Altiward flags the rest and waits for you to revoke them; with OutOfBandEnforcement set to enforce, the agent removes them itself, and the console shows Removed without a grant.

Four example findings as OCSF events

Altiward exports recorded sessions and findings as OCSF events. In Splunk they arrive with the sourcetype altiward:ocsf. The same event types go to Microsoft Sentinel or a syslog receiver.

Admin rights without a grantHigh

An account in the Mac's admin group without a recorded grant and outside your list of permanent admins. Investigate its purpose before deciding how to respond.

Admin account createdHigh

A new admin account appeared while someone held approved admin. Mapped to MITRE ATT&CK T1136.001, Create Account: Local Account.

Admin rights outlived their expiryMedium

The grant ran out but the rights didn't. Altiward reports it, or removes them when enforcement is on.

Altiward agent stopped checking inMedium

The server has missed expected check-ins from a Mac. Investigate the loss of visibility; the agent may still be checking locally.

Session evidence describes admin rights and detected account changes; correlate it with your existing telemetry to investigate commands and process activity. The full event is in Altiward's OCSF examples.
