macOS LAPS and just-in-time admin do different jobs

Altiward checks temporary admin rights while your MDM looks after IT's managed admin account. Here's how to list that account in Altiward, keep it outside enforcement and investigate unexpected admins on the rest of your fleet.

Last reviewed October 2026

What macOS LAPS covers

In Intune

Keep the managed IT or break-glass account under Intune's control. Put its account name in Altiward's PermanentAdmins list so its standing rights are expected.

In Jamf Pro

Keep the managed administrator account under Jamf Pro's control. Use the same account name in Altiward's PermanentAdmins list.

What it leaves open

Once everyone works as a standard user, people still need admin now and then: a printer driver, an Xcode update. Use SAP Privileges for those temporary requests and Altiward to check the resulting rights.

Set up Altiward alongside LAPS

Keep LAPS for IT's account

Leave the LAPS account to Intune or Jamf Pro. Give it a fixed name, such as Intune's default Admin, so it's easy to list.

Keep your existing elevation workflow

Keep how people request admin today. Altiward checks the resulting rights. Its expiry policy alerts by default; enable enforcement to remove overdue rights.

Tell Altiward which accounts are managed

List the LAPS account in PermanentAdmins in Altiward's configuration profile. The example profile documents the setting. Altiward leaves listed accounts alone and checks other admins.

What Altiward does with your LAPS account

Excludes managed accounts
Accounts listed as permanent admins are excluded from unexpected-admin findings, from removal of admin rights nobody granted and from expiry enforcement.
Watches everyone else
Every other account in the admin group is checked. An admin account made on the side is still flagged as admin rights nobody granted. With OutOfBandEnforcement set to enforce, the agent removes it after a grace period.
Set through your MDM
The list comes from the configuration profile you deploy with your MDM. If someone changes it on the Mac outside your MDM, Altiward reports it as tampering.
Who used the LAPS account
That stays with your MDM. In Intune, the audit log records each time someone views or rotates the password.

List your LAPS account before turning on removal. With OutOfBandEnforcement set to enforce, a LAPS account left out of PermanentAdmins is removed from the admin group, because it counts as admin rights nobody granted. So is a hidden MDM management account. Without SAP Privileges, every admin who isn't a permanent admin counts the same way. Altiward never removes a permanent admin. Removal is off by default.

Questions

Where do we configure the permanent-admin list?

Set PermanentAdmins in the com.altiward.agent profile delivered by your MDM. Use the managed account's local short name. The example agent profile documents the setting.

How do we deploy Altiward through Intune?

Deploy the agent package and configuration profiles alongside SAP Privileges. The Intune deployment checklist covers agent settings, permanent admins and deployment checks.

Does LAPS remove admin rights from users?

Not by itself. Intune's enrollment profile can create the person's account as a standard user, but LAPS manages only IT's admin account. It doesn't notice admin rights given to anyone else later.

Will Altiward flag our LAPS account?

Not once it's listed as a permanent admin. Until then, it's flagged like any other admin nobody granted, and with OutOfBandEnforcement set to enforce it's removed from the admin group.
