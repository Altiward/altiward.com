Reporting a security problem

Altiward is a security tool, so we want to hear about weaknesses in it. Here's how to report one, what's in scope, and what you can expect from us.

Report a vulnerability privately

01

Email us privately

Email hello@altiward.com with “Security report” in the subject. Include the affected Altiward component. Please don't open a public issue or post vulnerability details.

02

Tell us what you found

The affected component and version, the steps to reproduce it, and what an attacker could do with it. Leave out real fleet data and secrets.

03

We work on it with you

We acknowledge reports within five working days, keep you posted while we work on a fix, and agree disclosure timing with you. See the project security policy for supported versions and the reporting process.

What's in scope

In scope

The Altiward agent on macOS, including its tamper checks and how it records and removes admin rights. A way to stop or bypass the agent without it going on record is exactly what we want to hear about.

The Altiward server and console: the API, the console, sign-in, and delivery to SIEMs.

altiward-forwarder: the relay, on-Mac hook and event delivery. altiward-siem: the detection rules, searches and deployment templates.

altiward.com, this website.

Out of scope

Someone else's Altiward server. Teams run their own servers, and we can't give permission to test them. Test an installation you run yourself.

SAP Privileges itself. Report those to SAP, through the SAP Privileges repository.

Denial of service, spam, social engineering and physical attacks.

Get a copy to test

The agent, server and console source and install guide are on GitHub. Test only systems you own or have permission to assess.

What you can expect from us

Good faith
If you act in good faith and follow this page, we won't take legal action against you for your research.
Credit
With your permission, we'll credit you in the release notes for the fix.
No paid bounty
There's no paid bug bounty right now.
